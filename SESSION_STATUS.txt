Phase F.2 (consent flow fix — CRITICAL):
  Root cause: AdManager.requestConsent was called once from MainActivity, but
  the _isConsentObtained StateFlow was only WRITTEN, never READ. Ads loaded
  unconditionally 500ms after Application.onCreate, before consent had even
  started — in EEA/UK/CH this served ads to users before they consented.
  Fix:
  - requestConsent now uses ConsentInformation.canRequestAds() (true when user
    consented OR no form required in their region) instead of synthesising
    "obtained" on error paths. Removed 4 places that wrote
    _isConsentObtained=true on UMP errors.
  - All four ad-load paths now gate on _isConsentObtained:
      loadInterstitial / loadRewarded — early-return when !consent
      resetFailureCounters (foreground re-entry) — early-return when !consent
      startBannerRefresh (first banner load + refresh loop) — early-return
      AdManager.onConsentResolved(Context) — new hook fires first banner load
        + restarts refresh loop after consent resolves
  - LofigaApplication init coroutine: OneSignal inits immediately (push
    isn't personalised); awaits isConsentObtained.first { it } with
    60-second withTimeoutOrNull fallback; skips ad init on timeout/no-consent;
    calls onConsentResolved(Context) after init to kick the banner.
  - UMP 3.1.0 exposes canRequestAds() as a METHOD (not a property) — every
    callsite uses the () form.
  Commits: 6b21e4e (consent flow gate), 1ff407c (canRequestAds() fix)

Phase F.3 (audio edge-case fixes):
  - setHandleAudioBecomingNoisy(true) added to ExoPlayer.Builder — headphone
    unplug now pauses playback (Android UX convention + Play review safety).
  - hasAudioFocus + re-request focus in play(): AUDIOFOCUS_LOSS now clears
    hasAudioFocus + nulls audioFocusRequest; play() early-returns with a
    user-facing error ("Another app is using audio") if consent would be
    denied; otherwise re-requests focus before resuming.
  - initEffects vs releaseEffects race fixed: removed the
    scope.launch(Dispatchers.Default) wrapper — initEffects now runs inline
    on the Player.Listener callback thread, eliminating the half-built
    audiofx leak on rapid track switches.
  - onAudioSessionIdChanged listener added: re-runs initEffects() on the new
    session id after a routing change (BT disconnect); initEffects() now
    releaseEffects() first (defensive) so re-binds don't leak.
  Commit: 438524b (headphone + focus), c84ebf8 (init race + routing rebind)

--- LIBRARY SCREEN ---
Design a mobile Library screen for the Lofiga Android app — the screen where
the user browses all the songs on their device to pick one to slow down + reverb.

DESIGN SYSTEM (apply strictly to every element):
- Light theme is the DEFAULT. Pure white #FFFFFF surfaces everywhere — no dark
  gradients, no glassmorphism, no multi-color backgrounds.
- Cards/surfaces white with a subtle 1px outline border #EEEEEE, NO heavy
  shadows.
- Single restrained accent colour: deep indigo #1F3A8A, used sparingly only on
  primary actions/CTAs and the active bottom-nav indicator.
- Ink text near-black #111111 for headings, gray #666666 for body, #999999 for
  tertiary.
- No colourful gradients. No purple. Calm, beginner-friendly, like a 2026
  Material 3 design from a top Play Store utility app.
- Material 3 type tokens. Inter font family throughout.
- Generous whitespace, 16dp outer padding, 12dp inner card padding, 48dp min tap
  targets, 8dp corner radius on inputs, 12dp on cards, full pill on primary
  buttons.
- Material 3 NavigationBar at bottom: 4 tabs (Home, Library, Player, Settings),
  surface white, near-black icons + indigo pill indicator above active tab, gray
  when inactive, short text labels below each icon. Active tab is "Library".

LIBRARY SCREEN CONTENT:
- Top app bar: white background, title "Library" left-aligned (headline-medium),
  no back arrow (root tab). A search icon button on the right.
- A search text field directly below the app bar (outlined, thin gray border,
  8dp radius, leading search icon, placeholder "Search songs or artists").
- Sort/menu chips row: 3 FilterChips horizontally ("Recent", "Title A-Z",
  "Artist A-Z") + a "Mood" overflow icon button on the right. Active chip uses
  indigo outline + indigo text, inactive chips white outline + near-black text.
- Mood filter chips row (only visible when any mood tag exists): 4 chips — All,
  Chill, Mid, Energetic — same chip styling as the sort row.
- List (LazyColumn) of device tracks: each row a flat card with no border, just
  bottom divider line #EEEEEE: track artwork thumbnail (48dp, 8dp radius) left,
  title (one line, body-large, near-black), artist (body-medium, gray), duration
  (label-medium, tertiary) on the right. Tapping a row loads it into the Player
  and switches tab.
- Empty state: centered circle icon + "No tracks found" + subtitle "Pull to
  refresh or check storage permission" if device has zero tracks.
- Loading skeleton: shimmer placeholder rows when content is loading.
